# ADR Campus v0.2 — Identity and Application Security

Version 0.2 inserts an explicit identity and security release before ADR authoring begins. Its purpose is to establish who may enter ADR Campus and which active members hold maintainer authority, so later workflow releases do not build application commands on placeholder authorization.

## Included

- Browser authentication through Keycloak using the OpenID Connect authorization-code flow with PKCE.
- Secure application cookies and Keycloak-compatible sign-out.
- Provider-neutral external-directory contracts in Aetheric Runtime.
- A Keycloak directory provider for identity, group, and group-roster lookup.
- Configuration by exact Keycloak group name or stable group identifier.
- An active roster derived from the configured member and maintainer groups.
- Active-member authorization for the ADR Campus application.
- Active-maintainer authorization for administration and draft-recovery routes.
- Fail-closed behavior when current directory authority cannot be established or the role configuration is inconsistent.
- Startup validation for missing or identical member and maintainer group settings.
- Correct Member and Maintainer labels in the roster and account presentation.
- A reversible **View as member** presentation mode for maintainers.

## Security Boundary

Keycloak remains authoritative for identities, enabled state, and group membership. ADR Campus does not create local user accounts or provide operations that change SSO membership.

Maintainer authority requires an enabled identity to belong to both configured groups. Navigation visibility is a convenience only: maintainer-only routes enforce authorization independently. **View as member** changes presentation but never changes the authenticated identity or bypasses server-side policy enforcement.

Directory failures and inconsistent group assignments do not become negative membership facts or partial rosters. ADR Campus denies access when it cannot establish sufficiently current authority.

## Deliberately Deferred

Version 0.2 does not implement:

- durable application membership projections or membership-transition history;
- draft creation, editing, recovery, expiry, or cleanup;
- proposal and decision commands;
- ADR discovery, search, or lifecycle history;
- organization renaming; or
- supersession.

Those capabilities remain defined by the product stories and are sequenced in the [delivery roadmap](../roadmap.md).
